# 1.2.1 模型资料同步修复

问题：目录67个，前端只取当前页模型并Take(60)，worker/服务同步同样限制60；任务摘要未展示已过滤的失败信息，处理中下一条进度又覆盖了旧失败文字。

行为：未选模型时，models.sync接受scope（rootId、query、types、families）及downloadCovers；明确选择时保留ids接口。目录、搜索、类型、模型系使用与列表相同的SQL筛选；提交时在库内冻结ID，逐批120项读取，不向前端载入完整清单。资料更新造成的类型/家族变化不会改变本次范围。

model_sync任务增加issues数组，只包含固定code/count，不含文件名、路径、哈希、提示词、密钥或上游正文。失败类别独立存储，处理中、完成后均可查看。密钥/限流导致提前停止时保留真实processed，并显示未处理数量。取消（包括handler执行前）及关闭清理快照，同步记录/资料临时缓存各限16条。

检查：相关Python106项，Core302条，Civitai反馈17条；原生100%/150%字体场景各7项。独立代码评审另外验证130项跨120批次全部处理、queued取消快照归零；修正本地文件操作错误文案。所有测试使用独立生成的67/130个惰性文件、合成HTTP或假客户端，没有真实资料读取和联网查询。发布和清理回执另存verification-1.2.1。
